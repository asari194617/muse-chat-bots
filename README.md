# muse-chat-bots

Muse（AIアシスタント）とチャットで対話するための自作常駐Bot集。Discord版とSlack版があり、
どちらも同じ「橋渡し方式」で動く。

## 橋渡し方式

```
[Discord / Slack]
   Bot がオーナーのメンションをキュー (JSONL) に記録
        │  (SSHで定期同期)
        ▼
[Muse の実行環境]
   フックがキューを検知して Muse を起動
   Muse が文脈を読んで返信文を作成し、Bot経由で返信
```

Bot自体はメッセージの受付と返信の配送だけを担当し、対話の中身はClaude側が生成する。
Botは常駐マシン（systemdユーザーサービス）で動き、Claude側の環境が再起動してもBotは落ちない。

## 構成

- `discord/` — Discord版 `asari-muse`（discord.py、メンション/DM対話、コマンド一式）。詳細は `discord/README.md`
- `slack/` — Slack版 `asari-muse`（slack_bolt、Socket Mode、オーナーのメンション/DM対話）。詳細は `slack/README.md`

## 設計方針

- **名前空間ポリシー**（Discord版）: 他の人のBotと同居する前提で、汎用コマンド名を占有しない。
  起動はBotへのメンションか専用プレフィックスのみ、スラッシュコマンドもBot名のグループ配下に集約
- **オーナー専用**: 対話に応答するのは登録したオーナーだけ。他のメンバーからのメンションには最小限の案内のみ
- **秘密情報は含まない**: トークンは各マシンの `.env`（Git管理外、権限600）でのみ保持し、
  オーナーID等の個人設定ファイルもリポジトリに含めない
- **運用ルール準拠**（Slack版）: ワークスペース管理者のルールに従い、自発投稿・他メンバーへの
  自動メンション・大量投稿は行わない

## セットアップ

各BotのREADME（`discord/README.md` / `slack/README.md`）を参照。
大まかには「プラットフォーム側でアプリ/Botを作成 → トークンを常駐マシンの `.env` に設定 →
systemdユーザーユニットを有効化」の流れ。
